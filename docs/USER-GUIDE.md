## 它是怎么跑的

```
QQ 客户端
   ↕  （QQ 协议）
NapCat
   ↕  （OneBot v11 / WebSocket）
qfish（DSH 插件）
   ↕
DeepSeek Harness：模型、会话、工具
```

- qfish 本身不发消息，它把收到的消息整理成一轮对话，交给 DSH 的 agent；
- 模型决定回不回、怎么回，再通过 qfish 调 OneBot 接口发出去；
- 每个群、每个私聊对应 DSH 里的一个会话。

## 配置项

配置在 DSH 的插件设置里，入口是 **qfish**。

| 键 | 默认 | 说明 |
|---|---|---|
| `transport` | `forward-ws` | 连接方式：`forward-ws` / `reverse-ws` / `http` |
| `url` | `ws://127.0.0.1:3001` | OneBot 的 WebSocket 地址 |
| `accessTokenRef` | `ONEBOT_ACCESS_TOKEN` | 令牌的 DSH 凭据名；NapCat 没设 token 就留空 |
| `selfId` | 空 | 机器人 QQ 号，留空自动识别 |
| `respondToPrivate` | `false` | 是否处理私聊 |
| `respondToGroup` | `true` | 是否处理群聊 |
| `groupMentionOnly` | `true` | 群里只处理被 @ 或叫名字的消息 |
| `consoleEnabled` | `true` | 是否启动控制台 |
| `consolePort` | `8090` | 控制台端口，被占用会自动顺延 |
| `consoleListen` | `127.0.0.1` | 控制台监听地址，服务器上要改成 `0.0.0.0` |
| `consoleToken` | 空 | 控制台令牌，留空自动生成并保存 |

行为参数在**控制台**里改，不在这里。见[控制台](#控制台)一节。

## 人设

人设是纯 markdown，存在：

```
<profile>/onebot-data/persona/
```

- 按文件名排序拼接，比如 `1-persona.md`、`2-rules.md`，前缀数字决定顺序；
- 改完下一条消息生效，不用重启；
- 控制台「肥鱼底色」里可以直接改，保存即写回文件；
- 它会被放在提示词的最前面，比默认行为描述优先级高。

**写法建议**

- 写「你是什么样的人」，不写「你要像个人」；
- 具体行为比形容词有用：「被骂就骂回去」好过「性格强势」；
- 不要写「你是 AI」这类自我说明。

## 记忆

**存什么**

只记长期有用的：身份、长期偏好、重要约定、关键经历。寒暄、当天心情、一次性的事不记。

**存在哪**

```
<profile>/onebot-data/memories.json
```

按 QQ 号分组，群聊和私聊共用。

**上限与压缩**

- 每人最多 45 条；
- 超过后，把最旧的 18 条交给模型压成更短的条目，再写回去；
- 单条太长也会被压缩；
- 标了 `pinned` 的条目不参与压缩。

**怎么用**

每轮对话会把这个人相关的记忆挑几条注入提示词，不是全量塞进去。

**成本**

记忆本身不贵，贵的是它们会进入每轮上下文。记忆写得太长，每句话都在为它付费。

## 会话与轮换

**一个群一个会话**

群聊的会话键按群号算，不是按人。同一个群里，所有人共用一段上下文。

私聊按人算。

**什么时候轮换**

- 轮次到 30，或
- 累计字符到 40 万。

轮换时：

1. 把旧会话压成一段摘要（≤150 字）；
2. **私聊**还会压一条记忆；**群聊不写记忆**（记忆交给聊天中按人主动记）；
3. 这一轮里说过话的人，好感度各向 50 回正 5 点；
4. 删掉旧会话目录；
5. 新会话带着摘要继续。

**摘要怎么用**

新会话的第一条消息里会带「上一段对话的压缩摘要」，所以它接得上话，但细节会丢。

**重启会怎样**

轮次和字符数存在 `state.json` 里，重启后恢复，不会归零。

**问题：会话被归档**

DSH 如果把 qfish 的会话标成「已归档」，每轮都会直接 `blocked`，模型一次不跑。处理办法见[排障](#排障)。

## 群聊和私聊的行为

**群聊**

- 被 @ 或被叫名字：一定进入处理；
- 没被叫：按概率接话，默认 5%；
- 认识的人（有联系人档案）概率更高，默认 10%；
- 一次没接，会攒着，下一条消息一起处理；
- 消息有缓冲（默认 1.2 秒，群聊自动 ×1.5），连着发几条会合并成一轮；
- 缓冲和连发间隔在控制台里填的是**私聊**的值，群聊自动是它的 1.5 倍。

**私聊**

- 全部处理，不看概率；
- 没有「已读不回」的设定，除非模型决定不说话。

**回复预算**

- 每人每分钟最多 6 次回复；
- 超了就不回，等下一条。

**发送节奏**

- 同一个群里的所有出站消息共用一个间隔（私聊设置的 1.5 倍）；
- 一条回复拆成多条时，逐条发，中间隔这个间隔左右。

**闭嘴**

群里有人嫌它吵，可以把它静音；静音只对那个人生效，不影响别人。

**被骂**

会用群里「骂人的黑话」回嘴，不道歉、不讲道理；「普通的黑话」只用来听懂，不拿来骂人。

## 社交

**联系人档案**

```
<profile>/onebot-data/contacts.json
```

存 QQ、名字、你让它的称呼、备注。跨群、跨私聊通用。

**认人**

- 聊满一定轮次还没称呼，会主动问一次；
- 你说「以后叫我 XX」会直接记下；
- 管理员可以改别人的称呼。

**好感度**

- 0–100，存在 `mood.json`，只对社交名单里的人生效；
- 名单外的人固定 50，加减和回正都不参与；
- 加减有冷却：每 N 轮才允许加一次或减一次（默认 6 轮），档位随数值即时变；
- 会话轮换时，这一轮说过话的人各向 50 回正 5 点；
- 档位：≥75 卖萌粘人、11–25 冷淡、≤10 暴躁；
- 好感 ≤25 时推荐字数打折（≤25 打三分之二、≤10 打一半）；
- 尺度也跟着好感：≥75 完全放开，其余档位允许软色情和稍大尺度，但不过火；
- `/mood` 查看，`/setmood` 设置（管理员）。

## 看图

- 收到图片会作为附件进入上下文，模型直接看；
- 图片不会重复进上下文，避免浪费；
- 群里没被叫、也没接话的图片，不会触发模型。

**回头看之前的图**

你说「看图」「刚才那张」「上面那张图」，它会从最近 10 张里找出来附上。

触发词：看、瞅、瞧、认、存、要、拿、发 + 图/照片/刚才/那张。

## 看视频

只支持 B 站（BV 号、b23 短链、分享卡片）。

**流程**

1. 调 B 站接口拿标题、UP、简介、时长；
2. 时长超过 10 分钟直接拒绝，并说明太长；
3. 拿字幕（带时间戳）；
4. 按分钟切画面，每分钟一张 3×3 九宫格；
5. 字幕、九宫格、弹幕、热评一起交给视觉模型；
6. 模型写摘要和感想，存进观看记录。

**限制**

| 项 | 默认 |
|---|---|
| 视频时长上限 | 10 分钟 |
| 同一视频缓存 | 10 分钟 |
| 同一个群一分钟内 | 1 条 |
| 全局每小时 | 20 条 |

**什么时候会看**

- 私聊：发了就看；
- 群聊：被 @ 或叫名字时看；没被叫的群里不看；
- 短链（b23.tv）：不点开，直接说不想看。

**观看记录**

```
<profile>/onebot-data/bili-memory.json
```

最多 50 条，写摘要和感想。控制台能看、能删。

**主动分享**

默认关闭（`proactiveVideoChance: 0`、`chatVideoChance: 0`），开了会从观看记录里挑视频发出来。

## 内容工具

| 工具 | 说明 |
|---|---|
| B 站 | 找视频、看视频、发分享卡片 |
| 音乐 | 网易云 / QQ 音乐卡片 |
| 表情包 | 收到图判断是不是表情包，按概率存；发的时候按关键词挑 |
| 搜图 | pixiv、booru、以图搜图 |
| 联网 | 搜索、抓网页正文 |
| 提醒 | 「明天九点提醒我」，到点发消息 |
| 群管理 | 禁言、踢人、处理加群/好友申请、群公告 |
| 跨群发消息 | 管理员可以指定某个群或某个人发 |
| `/dsh` | 让机器人跑服务器命令，仅 DSH 后台权限 |

**表情包**

- 存表情的概率 = 表情概率（默认 0.5）；明确说「存」时 100%；
- 每人每小时最多存 10 张；
- 发的时候会挑场合：刷屏不发、同图不连发。

## 控制台

**打开方式**

```
http://地址:8090/?t=令牌
```

令牌来源：配置里的 `consoleToken`，或 `<profile>/onebot-data/console-token.txt`，或启动日志里「控制台已启动」那行。

**页面**

| 页 | 能做什么 |
|---|---|
| 肥鱼底色 | 改人设、语言规则、表情规则、场景规则、杂项 |
| 肥鱼库 | 黑话表、禁词表、语言模仿表、表情库、梗百科 |
| 功能配置 | B 站登录、Cookie、代理、贴吧 |
| QQ 控制 | 行为参数、会话、待办、社交、运行日志 |

**行为参数**（都在这一页）

| 项 | 默认 | 说明 |
|---|---|---|
| 回复条数上限 | 4 | 一次最多拆几条发 |
| 每条字数上限 | 12 | 单条最多多少字 |
| 接话概率 | 5% | 群里没被叫时的接话概率 |
| 认识的人接话 | 10% | 有档案的人 |
| 表情概率 | 0.5 | 发和存共用 |
| 回复预算 | 6 次/分 | 每人每分钟 |
| 发送间隔 | 2000ms | 同群出站消息 |
| 消息缓冲 | 5000ms | 连发合并 |
| 会话次数上限 | 30 | 到点轮换 |
| 会话字符上限 | 40 万 | 到点轮换 |

**访问控制（必配）**

出厂默认是全拒：`allowlist` + 空名单，任何人都触发不了它。

```yaml
respondToPrivate: true
userAccessMode: allowlist
userIds: ["你的QQ号"]
groupAccessMode: allowlist
groupIds: ["你的群号"]
```

想全开也行，自己承担风险：

```yaml
userAccessMode: blocklist
userIds: []
groupAccessMode: blocklist
groupIds: []
```

不配置的话，机器人上线也不会回任何消息。`respondToPrivate` 默认 `false`，需要私聊就显式打开。

**会话页**

看每个群/私聊的轮次、字符数、最后活跃时间，能强制轮换。

**运行日志**

最近的错误和关键事件，排障先看这里。

## 排障

**它不回我**

1. 群里没 @ 也没叫名字，可能没接话；
2. 看控制台「运行日志」有没有报错；
3. 私聊一句试试，排除群聊概率问题。

**有会话，但一轮都不回（blocked）**

DSH 把会话标成已归档了。退出 DSH，编辑 `~/.dsh/storages/workspace.json`，删掉 `archivedSessionIds` 里以 `onebot:` 开头的条目，重启。

**控制台显示离线**

Windows 早前版本用了 Linux 命令检测，现在已修。还显示离线就看 3001 端口通不通。

**控制台打不开**

- `consoleListen` 是不是 `0.0.0.0`（服务器）；
- 端口有没有放行；
- 地址里带没带 `?t=`。

**QQ 突然掉线**

同一个 QQ 在两个 NapCat 上登录会互踢。确认只有一个地方登着。

**NapCat 改了配置不生效**

确认改的是当前实例的配置。桌面版里 SnowLuma 和 napcat 后端的配置文件不在一处，改完要重启实例。

## 成本

**花在哪**

1. 上下文：每轮都要重读历史，历史越长越贵；
2. 看视频：读图是主要开销；
3. 记忆和人设：每次都会带上，太长就一直在付费。

**怎么降**

- 会话轮换调勤一点（比如 15–20 轮），避免单次上下文过大；
- 视频时长上限、每小时上限调小；
- 人设和记忆写短；
- 关掉主动分享。

**看实际用量**

- 控制台「运行日志」里没有费用数字，只有调用记录；
- 更细的用量要看 DSH 那边的会话统计。
